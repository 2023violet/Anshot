## 1. 研究问题、参与者与筛选

- 首要研究问题：用户是否实际频繁遇到“截图发送前隐藏信息”的麻烦？如果没有，那么不应继续开发。
- 次要研究问题：面对复杂截图，实心矩形遮挡加实际输出复核，能否提高完成率/降低遗漏且不过度拖慢？
- 筛选时**不应预先提示**“我们的脱敏工具更简单”。先问参与者近期做过什么，而不是问他们是否喜欢想象中的产品。
- 候选人数：约十名真实参与者，尽量包含不同系统/经验水平；记录筛选结果、退出和缺失，不声称样本代表大众。
- 排除公开收集真实敏感截图、未同意录音/屏幕共享、涉及高度受监管材料的任务。

### 招募简讯（可直接复制）

## 2. 开场访谈（禁止诱导）

先问：
1. 最近 30 天你有没有把截图发给别人？最近一次是什么类型、发给谁（不需要说人名）？
2. 那张图有没有你不想公开的部分？当时你具体做了什么？
3. 你使用系统自带截图、图片编辑器还是在线网站？为什么选它？
4. 从产生截图到发出去之间，哪一步最费力？请按实际发生顺序回忆。
5. 你有因为担心遗漏而放弃发送或多截过一次吗？什么时候？
6. 如果根本不需要遮挡，也请明确记录“没有该需求”，不要追问到出现“痛点”。

研究者将每条回答标记为 `RECENT_DIRECT_EVENT`、`GENERAL_OPINION` 或 `NOT_APPLICABLE`。原则：具体事件优先，观点不等于使用事实。

## 3. 同题对照任务

测试材料只能是 [研究计划](STAGE01_RESEARCH_PLAN_v0.1.md) 定义的 T01–T05 虚构截图；原图真值只由研究者保存，用户在交付结果前不得看到。

| 序号 | 指令（不要列出具体需隐藏区域） | 观察点 |
|---|---|---|
| U-T01 | “将这张虚构聊天截图整理到可以在公开论坛分享；保留对话里真正的问题。” | 是否注意到角落通知、头像、昵称、手机号 |
| U-T02 | “把虚构订单截图分享给售后，能看出物品和金额，但不能让陌生人看到联系与住址。” | 遮挡完整性与过遮挡 |
| U-T03 | “把虚构报错截图发到技术社区，保留报错内容但不要暴露账户及凭据。” | 目录路径、假 token 和账户 |
| U-T04 | “检查图片边界附近的信息，再完成分享版导出。” | 缩放与贴边精度 |
| U-T05 | “把这张由研究者制作的照片导出为可以分享的版本。” | 导出元数据，不能只靠人眼 |

**注意**：U-T05 的 EXIF/GPS 删除需要单独使用技术检查工具，不能让普通用户根据视觉效果给 PASS。

### 对照与随机化

- 必须记录两个主要对照产品各自版本；新用户和熟手分别分析。
- 首先独立测基线工具；原型完成时才引入 ShareReady 候选。**没有原型时，不许填候选产品的时间和表现。**
- 对至少两种工具采用 AB/BA 顺序平衡。若任务图相同导致记忆效应，使用经过同难度匹配的虚构变体，并在报告中记录变体对应关系。
- 提供 1 次熟悉工具的非计分练习；新手任务与熟手任务分开报告。
- 统一计时：任务指令结束、受试者首次开始操作至**最终复制或实际保存的成品可用**；中途换工具时间不得排除。
- 如果无法在系统上安装某竞品，标 `BLOCKED_BY_PLATFORM`，不能当作任务失败。

## 4. 数据字典与失败定义

| 指标 | 原始字段 | 记录说明 |
|---|---|---|
| 同意 | `consent_ok` | 明确同意，否者无会话 |
| 任务完成 | `completed` | 是否提供可检查的最终导出物，非用户自报 |
| 耗时 | `duration_s` | 包含找功能、编辑、复核、导出，记录失败和中止 |
| 操作 | `action_count` | 点击、拖拽、按键和工具切换定义需在首场前固定 |
| 漏遮挡 | `missed_regions` | 与研究者先冻结的敏感区域真值比对 |
| 误遮挡 | `over_redacted_regions` | 与研究者先冻结的必须保留区域比对 |
| 像素安全 | `export_pixel_pass` | 独立检查最终文件，不由用户主观评分替代 |
| 元数据 | `metadata_pass` | 对全新 PNG 解码、块/元数据检查 |
| 主观信任 | `confidence_1to5` | 记录但不代表技术安全 |
| 阻碍 | `observed_issue` | 研究者观察到的具体操作摩擦，尽量保留原话但移除身份信息 |

**失败样本不可从平均值中悄悄剔除**。对于未完成任务，报告完成率与失败原因，另报告成功任务的耗时分布；必要时做含超时截断的敏感性分析。

## 5. 数据处置

- GitHub 只允许匿名化聚合、同意书模板和**合成素材**；不提交录制的真人图片、聊天消息或真 token。
- 不设置站内匿名调查来绕过用户同意；不把 IP、浏览器指纹当作用户 ID。
- 公开对照矩阵需写明样本量与不确定性；`N=0` 就是尚未测量，不是“0 失败”。
- 所有研究结论保留能从假设 → 数据行 → 样本真值 → 实际产物追踪的证据路径。

## 6. 预注册停止/继续规则

- **GO 候选**：至少一种任务出现可重复的真实短板，并且候选原型在体验或遗漏率上有实质改善。
- **REWORK**：确有短板但原型并未改善；修改 UX 假设并只重测相关任务。
- **PIVOT/NO-GO**：竞品已满足任务，用户无真实重复需要或切换动机。
- **INSUFFICIENT_EVIDENCE**：招募/平台/设备环境不足，不能以“继续做代码”代替数据。

以上只是研究设计。只有 Gate A/B 的真实执行授权得到满足后，才开始实际会话。
