# SR-RES-009｜S04 招募伦理、同题实验预注册与退出规则

> **2026-10-15 · DRAFT v0.1 · S04 IN_PROGRESS · 0 实际参与者**  
> 由研究执行方预编制的协议，不是假定已获得独立伦理委员会审查或数据保护法律意见。没有研究者账户、参与者报名、录音、授权同意或支出记录。完成文案与排程不等于研究已执行。

## 1. 研究目的与不可扩大边界

原 Gate B S04：形成**可复核的非诱导筛选、单独知情同意、身份信息最小化处理及平衡随机顺序方案**，并如实记录招募状态。S05a/S05b 才采集真实会话，当前未经实际招募不推进。

首要 A1 问题：普通人在过去 30 天是否真正发生过“截图分享前隐私遮挡”，现有工具哪里使其多花时间或遗漏，是否值得使用独立 Web 工具。这个目的既可能支持继续，也可能证明**没有足够产品差异化**。

研究只对已存在的 **Redacted（工具 A）** 与 **Redaction Tools（工具 B）** 进行自发探索与实际任务；**没有 ShareReady 原型**，禁止让参与者假装使用尚不存在的应用。不得以预知坐标脚本完成率代替参与者的自主识别与操作。

## 2. 参与资格与非诱导筛选

- 必须自愿、成年人、理解研究目的并能使用研究语言与浏览器；任何参与者可不说明原因中止。
- 不强迫必须遇到打码问题才能入组，否则会将“痛点存在”人为制造成筛选条件。
- 询问过去 30 天截图的分享次数区间 `0 / 1–2 / 3–5 / 6–10 / 11+`；另问其中**真正需要隐私遮挡的次数**（允许为 0），记录与最近一次实际经历的差别。
- 要求说出最近一次真实发生的截图分享过程，但**不需要任何姓名、账号、住址、用户原图或聊天内容**。
- 记录操作系统、浏览器主要版本与对两款工具的先前熟悉程度；不记录公网 IP、浏览器指纹或真实个人文件。
- 招募目标：约 10 位，优先覆盖至少两个常用操作系统以及近 30 天“实际遮挡过”和“从未遮挡过”者。不是概率样本，不宣称代表普通大众。

## 3. 同意、数据隔离和费用

- 必须在研究开始前展示 [同意与筛选文本](STAGE01_S04_CONSENT_AND_SCREENERS.md)，记录是否同意参加；录像、录音需要**另行明确同意**，不默认为同意。拒绝录音不影响参加无录音研究。
- 所有试题使用仓库 [虚构 PNG](fixtures/manifest.json)。不得要求上交真实私人截图、访问真实个人账号，也不得收集用户的真实密码、token、手机号、地址或账户订单。
- 对研究会话使用随机化 `P001` 等匿名代号；招募联系信息（若后续有）应离线独立保存、最小化保存、限制访问，并在研究完成/撤回后按事前声明删除。**不要**把招募邮箱、联系记录、真实设备标识上传 GitHub。
- 公开仓库只收录被试匿名聚合、合成任务原图、对照工具导出与经身份剔除的统计；需对自由文本再做人审，避免意外出现间接身份标识。
- 此时未建立研究者平台账号、预算或招募渠道。付费平台费用、激励、购买套餐与对外发布招募文案需另行取得实际授权；计划表中的 10 个槽位不是 10 位受试者。
- 事前告知记录保存期，建议研究原始匿名指标最长保留 30 天用于复核，之后仅保留无法识别个人的聚合结果。若参与者要求退出，按同意说明删除其尚可关联的记录。

## 4. AB/BA 对照与学习效应控制

`A = Redacted`、`B = Redaction Tools`。使用 [10 个虚拟招募槽位](STAGE01_S04_ALLOCATION_SLOTS.csv) 预分配每人的工具顺序、任务图。该表 **全部 `UNASSIGNED`**，不是实际完成名单。

- 工具顺序五人 AB、五人 BA，A/B 各使用 T01 五次、T02 五次；固定比例只是 **目标设计**，实际退出导致不平衡时照实报告。
- 每人连续做两种工具但使用**不同合成截图**，减少直接记忆具体遮挡区域；任务难度仍不同，因此必须使用被试/工具/任务三因素分层，禁止直接对两次时间算因果差异。
- 完成入组后才从预设槽位中按事先定义顺序/随机化规则分配，不按参与者表现挑选。
- 每场先执行相同的非计分操作练习，正式任务前不显示敏感区域真值。主持人不得指点“这里还漏了”，但可在参与者明确卡住后提供协议允许的统一最低限度提示，并记 `hint_used`。
- 两工具均从“截图已经准备好”开始计时，任务结束以**实际复制到目标位置或保存并重开 PNG 文件成功**为准；记录失败、放弃和无法安装，而非从样本中删除。
- Redaction Tools 的可选 AI 按原基线设为关闭，保留默认规则检测；如果之后比较 AI ON，必须另做标明变更的独立分组，不能并入本研究样本。
- 不能将 GitHub Actions 中通过空白点击恢复指针交互的操作直接教给所有用户当成“正常操作”；参与者遇到问题时需记录原始行为与提示/补救。

## 5. 指标与原始记录

遵守 [合同表头](COMPETITOR_TEST_CONTRACT.md) 并额外记录协议字段：

| 指标 | 必须定义 |
|---|---|
| `completed` | 用户完成导出并能重新打开成品；未达成记否，不能用“点过下载”冒充 |
| `duration_s` | 实际任务指令开始到成品可用的时长；失败也记录退出前耗时 |
| `action_count` | 鼠标点击/拖拽/键入/工具切换全部计数，连点与拖拽规则在首场前冻结 |
| `missed_regions` | 对照预先保存的敏感真值，使用实际导出像素，不由“用户自信”代替 |
| `over_redacted_regions` | 遮住必须保留的内容，独立计失败 |
| `export_pixel_pass` | 最终文件读取、像素区域判据及错误路径；不代表全面安全审计 |
| `metadata_pass` | 测试文件原始元数据与最终导出对照，使用专门 T05 技术 QA 而不要求普通用户判断 |
| `prior_experience` / `confidence_1to5` | 熟练程度和自报信任度，用于探索而非安全事实 |
| `hint_used` / `dropout_reason` | 对口头协助、无法完成和撤回如实记录 |

未完成的试次：公开 **完成率与失败原因**，另对成功试次提供耗时分布；不得只在成功用户中选择平均时长宣称效率优越。样本约 10，不能宣称统计显著性。

## 6. 预先冻结的继续 / 停止标准

- 用户近一个月从未遇到遮挡需求，或仅使用系统截图工具就足够时，**不强行把它转化为产品痛点**。
- 如果竞品能完成所有典型任务，并且用户没有迁移意愿，结论优先是 `PIVOT/NO-GO`。
- 如果有重复实际问题，但不具备实验环境/招募经费/知情同意，结论为 `INSUFFICIENT_EVIDENCE`，不能用虚构样本补齐。
- 任何真实用户会话都要在招募渠道可用、同意到位和研究协议评审之后再开始。产品 Rust 编码仍不允许。
