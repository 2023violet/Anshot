## 1. 证据边界

- **确定的用户约束**：Rust 为核心语言；免费、开源；先验证现有竞品，再正式设计 UI；走 deciding-and-executing 治理流程。
- **已证实的竞品文档能力（DOCUMENTED）**：Redacted 提供浏览器本地处理、手动遮挡、剪贴板复制、元数据移除、离线使用和本地 OCR/PII 检测；Redaction Tools 提供粘贴→检查遮挡→复制/下载；ShareX 提供截图→编辑→复制/保存的完整桌面工作流。详见 [研究计划](../research/STAGE01_RESEARCH_PLAN_v0.1.md)。
- **未证实（NOT_VERIFIED）**：有多少普通用户频繁遇到该问题、竞品对同一任务的完成率/速度、额外复核是否降低遗漏、目标用户是否会记得再次打开网页、Rust/WASM 在目标设备是否足够快。
- **不可先验假定**：免费、本地、复核、复制、AI 检测不是我们独占的创新点。

## 2. 定位与产品问题

### 工作定位（待 A1 验证）

在用户已经得到一张截图、准备分享给其他人时，协助其**准确地遮挡自己指定的信息**，检查最终生成的图像，并复制或下载结果。区别于完整截图套件，聚焦“分享前最后一步”。

### 目标用户（假设）

| 细分群体 | 近期典型任务 | 需要研究的摩擦 | 优先级 |
|---|---|---|---|
| 日常聊天与社交用户 | 分享聊天记录、群聊截图 | 头像、名称、通知可能被遗漏 | 研究 P0 |
| 普通办公/客服/电商用户 | 分享订单、收据、报错图 | 多个区域遮挡后保留关键说明 | 研究 P0 |
| 论坛及技术求助用户 | 分享设置、浏览器与错误截图 | 账号名、路径、令牌被无意公开 | 研究 P1 |
| 高敏感/受监管资料用户 | 身份证、病历、法院/金融案件材料 | 合规义务超出单一工具 | **非目标** |

用户角色是待访谈假设，不代表已有市场数量或使用频率证据。

## 3. 项目策略与非目标

- **首发载体候选**：桌面浏览器 Rust+WASM 静态 Web；最终架构须过 Rust 能力 SPIKE 与用户任务实测。
- **Rust 不可妥协边界**：核心像素变换、区域几何、编码输出及可独立验证的纯函数逻辑用 Rust 实现。
- **免费开源**：不设计注册、账号、分析跟踪、订阅付费墙或云存储；当前仓库已有 MIT 许可证，依赖与品牌仍须各自核查。
- **首发非目标**：AI/OCR 自动脱敏、人脸识别、PDF/视频、社交平台自动发布、浏览器扩展、复杂标注、模板市场、跨端同步、移动原生版、摄像头拍摄。
- **不可作出的安全承诺**：自动找到所有隐私信息、绝对匿名、满足某行业的合规要求。即使矩形遮挡技术正确，未标记区域仍可能泄露。

## 4. 可验证的用户故事

| ID | 故事 | 观察条件 |
|---|---|---|
| U01 | 作为桌面用户，我能粘贴或拖入一个**合成** PNG/JPEG 截图 | 从空状态进入有效画布，不发送上传请求；浏览器限制要明确反馈 |
| U02 | 我能为姓名、地址等选中多个矩形遮挡并调整范围 | 区域和裁剪边界正确；无需懂高级编辑概念 |
| U03 | 我能撤销/重做遮挡操作 | 恢复后导出与屏幕预览一致 |
| U04 | 我可以检查一张最终成品图，然后复制为 PNG 或下载文件 | 复制成功或得到明确的浏览器拒绝反馈；保存后可重新打开 |
| U05 | 当我的图片过大、格式不支持或读取失败时，能得到可理解的信息 | 无崩溃、卡死、隐式上传或吞错误 |
| U06 | 我能在处理过程中理解哪些信息是我**手动**遮挡的 | 无“软件已自动检查所有敏感信息”等误导性文案 |

## 6. 信息架构与状态模型（Stage 02 输入）

不预设多页站点。候选为单工作区五状态：

`EMPTY → LOADING → EDITING → OUTPUT_REVIEW → EXPORTED`；错误态 `ERROR_RECOVERABLE` 可返回原先有效状态；导出失败不得改变已编辑内容。

- 空状态：粘贴、拖放、选择文件；无需登录和导航层级。
- 编辑状态：画布、选中区域、遮挡、调整、撤销/重做、完成操作。
- 复核状态：真正导出结果、原图与遮挡预览**不得同屏意外暴露**；明确“请自行检查未被遮挡的区域”。
- 完成状态：复制成功、保存成功、失败及替代操作的区分反馈。
- 移动端：浏览器支持范围待查；不能承诺分享菜单接入。

## 7. 安全与隐私需求（产品契约，非验收结果）

### 威胁模型（最小集）

- **在范围内**：遮罩层未真正写入输出、坐标缩放导致漏像素、EXIF/GPS 残留、导出源图层、复制到剪贴板的还是原图、异常大图片引起内存耗尽、意外外部网络请求。
- **不在首版声称防护范围内**：用户未指定的敏感区域、社交平台二次传播、从未遮挡上下文推断身份、恶意扩展/浏览器环境、法律合规认定。
- **约束**：不支持 SVG/PDF/动画源文件作为 MVP 输入，避免任意脚本或多帧安全歧义；解码后转为受限制的像素表示，编码为新 PNG；后续对图像尺寸、内存和色彩/方向处理进行边界测试。
- **导出不变量**：对于经过几何变换映射的指定遮挡区域，每个目标像素必须由纯色替换；不能用 CSS 叠层代替真正的数据修改。
- **可靠性**：安全门禁失败时应阻止输出，而不是警告后放行。
- **网络**：承诺无用户图片上传前，须以 DevTools 请求检查、CSP 策略检查和源码依赖审计验证实际运行行为。

## 8. 成功指标与实验

| 指标 | 定义 | Stage 01 状态 |
|---|---|---|
| 使用频率 | 用户过去 30 天**实际**有过需要遮挡的截图分享次数（不引导提问） | NOT_VERIFIED |
| 任务完成率 | 规定时间内提交通过像素/遗漏判据的导出图数 / 总任务数 | NOT_VERIFIED |
| 效率 | 首个有效操作到可分享成品，按任务计秒；配合动作次数 | NOT_VERIFIED |
| 敏感区域遗漏 | 合成样本真值中未充分遮挡的必要区域数量 | NOT_VERIFIED |
| 过度遮挡 | 本应保留的业务区域被遮挡的数量/面积 | NOT_VERIFIED |
| 复用意愿 | 完成任务后愿意在同一场景再用的用户数，记录原因 | NOT_VERIFIED |
| 安全正确性 | 导出像素、元数据、剪贴板、网络和异常输入的实测测试 | NOT_VERIFIED |

研究探索门槛：约 10 名真实被试，其中至少 6 名独立讲出近期确实遇到过问题；建议对等任务达到 ≥20% 的完成时间中位数改善且遗漏与完成率不劣化，或者重复可见的遗漏下降且无不可接受额外步骤。阈值是**团队预设决策辅助**，不是统计显著性或市场规模证明。详见实验计划。

## 9. Rust 技术决策暂存（Architecture Decision Pending）

| 路线 | 原因 | 验证门槛 | 当前结论 |
|---|---|---|---|
| Rust + Leptos CSR + Trunk / WASM | Rust 驱动浏览器 UI、静态托管，零安装 | Web 剪贴板、图片大小、PNG 编码、首屏 WASM 加载与各浏览器适配 | **首选 SPIKE**，非冻结 |
| Rust core + Tauri 2 | 可嵌入现有截图/文件流程，系统能力更多 | 安装成本、Windows/macOS 行为、签名分发与系统权限 | 备选 |
| Rust core + Slint/egui | 原生桌面产品，交互/数据本地化 | 图片编辑定位、键盘/触屏操作、打包、跨平台一致性 | 备选 |

任何路线均保留一个不依赖 GUI 的 Rust 图像处理核心，并在 Stage 06 才决定实际 Cargo 依赖。不得为了框架偏好提前写代码。
