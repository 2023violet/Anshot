## 预案 if-then

1. 如果基线竞品已经完成我们试图解决的同一操作且时长/遗漏无劣势 → 立即降级独占卖点，不通过装饰 UI 制造差异。
2. 如果用户招募未达预设下限 → 报 `INSUFFICIENT_EVIDENCE` 并调整招募计划；不得虚构用户结果或用开发者自己代替全部样本。
3. 如果浏览器或 Rust/WASM 复制/图片重编码在关键平台不可行 → 不改变用户问题定义，先提议架构 SPIKE/载体切换并重过相关 Gate。
4. 如果发现竞品名称/商标与当前内部代号冲突 → 禁止公开品牌发布，先开展独立命名决策。

## 事前验尸：失败的最可能原因

- 问题实际频率很低 → S01/S04/S05 用“最近一次实际行为”筛查，避免态度题带偏。
- 同题对照顺序和经验不公平 → S03/S05 保存经验分层、计时起止定义与条件。
- 假的安全信任感 → 像素、元数据、剪贴板安全检测独立于 UI 满意度。
