# 决策卡：ShareReady V1.2 Windows Loopback HTTP 安全加固

- 日期：2026-10-16
- 结论：改后做（保留 V1.1 Rust/WASM 加 Windows 轻量启动器架构，限定独立分支安全加固，先红测，复核后才可讨论部署）
- 置信度及依据：高：在 PR #14 提交 c16b0953a4705a36b5c93a1645704ebd7a4cde7e 静态源码中可核对出 Host 未验证、Header 行长度无前置上界、EOF 边界问题；但 DNS 重绑定利用性还没有实测

## 目标
在不更改现有产品架构、不合并和不发布的前提下，用独立 Windows 原生 TCP 正负测试证明静态本地服务的 HTTP Host 和请求大小/EOF 解析边界安全且未破坏真实 Rust/WASM Chrome 正向功能。

## 成功标准
1. 正常 Chrome/Edge 访问 http://127.0.0.1:<动态端口>/ 的合法静态文件 GET/HEAD 正常，Windows 一键启动不需要额外安装依赖。
2. 所有接受的 HTTP 版本请求仅在存在一个准确匹配 Host: 127.0.0.1:<实际端口> 的 Host 头时提供资源；缺失、重复、错误域名/IP、畸形 Host、HTTP/1.0 Host 绕过均拒绝且不发送静态资源。
3. 请求行读取、单条 Header、Header 总字节和行数存在在接收前或增量解析时生效的明确限制；超限、EOF 无空行、超时均拒绝或关闭且不输出资源。
4. 固定路由白名单、仅监听 IPv4 127.0.0.1、POST/PUT=405、非法资源=404、HTTP CSP、Cache-Control no-store 与 nosniff 保持有效；没有 HTTP 上传路由。
5. 当前工程 HEAD 通过原生 Windows 原始 TCP N01–N11 正负测试、Linux Cargo 锁定核心测试、真实 Rust/WASM/Chrome 合成像素、Clipboard 和网络验收；机器日志与 HEAD SHA 对应。
6. 所有差异仅在独立工程分支，不改 V1.1 原 Draft、V1、E1、E2、main；新的 Draft PR 与独立审查意见可核验，同时 E1e 独立安全评审门禁仍不被绕过。

## 非目标
- 不引入 Tauri、Electron、完整网络框架、远端 API、登录或遥测。
- 不处理任何真实个人/私人截图，不自动声称安全认证。
- 不推送 main、不合并 PR、不部署、不发布、不删除项目数据或分支。
- 不自行冒充独立审查者，不自动确认 Gate A/B，不替代 Stage 01 真人需求验证。

## 关键假设
| # | 假设 | 若不成立的后果 | 状态 |
|---|---|---|---|
| A1 | Windows 轻量 TCP HTTP 启动器能够以有限代码改动做到正确的 Host、Header 和 EOF 失败封闭，并可由原生负向测试复现 | 必须重新比较完整 HTTP 框架、原生容器方案，不能以忽略威胁推进 | 未验证 |
| A2 | 严格 Host 校验与合理字节边界不会破坏现有 Chrome/Edge、Windows 正常启动 | 必须暂停上线判断并修正主机访问约定和兼容性测试 | 未验证 |
| A3 | 改动不影响现有 Rust/WASM 像素遮挡、元数据清理与本地 Clipboard / 下载契约 | 必须先回滚到成功基线并定向修复 | 未验证 |

## 止损条件
- 触发状态：出现可重复的合法 GET 失败、远端图片传输、Host 绕过、非白名单资源暴露、或代码/CI 证据源 SHA 不一致
- 期限：2026-10-23
- 动作：停止 V1.2 实现、保存最小负向输入与 CI 工件，回到 Gate A 重审方向，维持旧版 Draft 未发布

## 升级阈值
- 修复失败次数上限：2

## 最大风险
补丁只改善部分 HTTP 解析，却被误宣称为已消除 DNS 重绑定、拒绝服务或整个产品对真实私人图片的风险；当前 E1e 独立安全审查仍未签署。
