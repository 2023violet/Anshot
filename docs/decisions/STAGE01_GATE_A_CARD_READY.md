# 决策卡：ShareReady Stage 01

- 日期：2026-10-14
- 结论：改后做（只进入用户需求、竞品与产品定义阶段，工程代码暂不启动）
- 置信度及依据：中低；公开竞品功能明确，但用户任务数据、真实使用频率与体验优势尚未测量。

## 目标

用可追溯的竞品研究和真实用户任务证据，决定 Rust-first 免费开源截图发送前整理工具是否值得开发，并形成可以否决产品方向的 PRD。

## 成功标准

1. 四种以上具体替代方案的同任务对照矩阵附版本、环境、来源与证据等级，已公开声明的功能不得当作我们的独占卖点。
2. 至少五个不含真实私人信息的合成任务样本有可检查的目标遮挡区域、保留区域及导出真值规范。
3. 约十名真实被试的招募与同意流程、研究脚本及记录字段明确；实际访谈不足则标记样本缺失，不能虚构结论。
4. Stage 01 PRD 明确用户、JTBD、P0/P1/非目标、安全边界、成功指标、停止条件及每项未证实假设。
5. 针对 Rust/WASM、Tauri 与原生 GUI 形成以首发用户路径为依据的条件性比较，未做技术 SPIKE 不冻结 UI 框架。

## 非目标

- 不在本阶段编写或发布 Rust 应用、设置生产部署或引入支付/账号。
- 不在未经证明时宣称无遗漏、绝对匿名、优于现有同类产品。
- 不复刻现有同名产品的商标或品牌，不无授权逆向闭源竞品。
- 不因已有宽泛 GitHub 写入授权而跳过 Skill 的独立 Gate A/B 确认。

## 关键假设

| # | 假设 | 若不成立的后果 | 状态 |
| --- | --- | --- | --- |
| A1 | 用户近期实际遇到重复的分享前遮挡困难，且现有工具至少有一项可重现的体验缺口 | 暂停 Rust 开发，评估终止或选题转向 | 未验证 |
| A2 | 新的最终复核机制能降低遗漏且额外负担可接受 | 取消引导式复核 | 未验证 |
| A3 | Rust/WASM 能满足首发输入、导出、安全和性能约束 | 转向桌面候选或收窄首发范围 | 未验证 |
| A4 | 存在可公开使用、无明显冲突的正式产品名称 | 继续使用内部代号，不营销 | 未验证 |

## 止损条件

- 触发状态：约十名真实用户与至少两种同任务基线均完成后，仍无法复现有意义的体验短板，或测试证据明显支持既有免费替代产品优于新方案。
- 期限：2026-11-14
- 动作：暂停 Rust 工程，记录 NO-GO/PIVOT；样本不足则标记 INSUFFICIENT_EVIDENCE，不虚构结论。

## 升级阈值

- 修复失败次数上限：2

## 最大风险

需求频率低且竞争者已提供同样的本地遮挡、OCR 与结果检查；选择 Rust 可能带来开发满足感，却不会自动带来用户价值。
