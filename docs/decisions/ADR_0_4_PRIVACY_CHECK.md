# ADR 0.4-PRIVACY-CHECK：分享前检查（本机、辅助、由用户确认）

日期 2026-11-01 · 状态：用户已批准（0.4.0 计划，2026-11-01）

## 背景
0.3 的功能主要是追平竞品。安截的差异是“输出可信”，但用户平时看不见。竞品调研把“基于 OCR 的建议打码框”列为可能的空位（推断），PRD 把它推迟到 0.4，前提是 OCR 先稳定。

## 决定
- **四项功能：** 分享前检查、同词全遮、替换代替打码、出图自检。
- **时机：** 工具栏按钮（Ctrl+Shift+K），加上复制 / 保存后自动检查。图先交付，检查在 worker 线程上读刚交付的字节，只提示，不拦截；设置项 `check_on_share` 默认开。
- **确认：** 列表默认全选，用户确认才改图；一次应用只占一步撤销。自动遮挡没有被采用，因为误遮可能不被注意。
- **识别：** 仍用 Windows 自带 OCR，不加依赖。规则用 Rust 手写，不引入 regex。同一张图按 1、1.5、2 三种倍率识别后取并集；高图分段识别。
- **隐私：** 识别出的文字只在内存，不写盘、不写日志、不进历史；替换或关闭文档时清除。列表只显示首尾几个字符。
- **信任边界：** 建议框只在 Slint 层绘制，Rust 渲染看不到它，不可能进入导出。替换文字绝不由原文生成，也不保留部分原文；底色只取框外一圈像素的中位数，强制不透明；文字在遮挡之后绘制，放大镜和聚光灯都取绘制后的画面。标签单独放在 `Scene.labels`，没有标签时渲染路径不变，五张 V1 金样本和 scene-v1 ~ v3 不受影响。
- **措辞：** 界面只说“辅助检查”“成品里识别不出”，不说“安全”“无法还原”。

## 证据（MEASURED，合成图，代理执行，见 `spike/ocr/RESULT.md`）
- 留出集（未参与调参的号码和字体）：召回 90.2%、覆盖 97.7%、普通文字误报 10/360。这里的召回指“框到了这个位置”，类别或文字可能有误。
- 单一倍率只有 78%；门槛 90% 刚好通过，余量很小。
- 分类型：银行卡、邮箱、身份证约 97%；手机号、IP、密钥 81–84%。12–14 px 文字 83–87%，16–20 px 96–97%。
- 1080p 全屏三遍识别约 2.3 秒（本机）；带遮挡时自动检查约翻倍，都在 worker 上运行。
- 留出集在移植到 Rust 时看过一次漏检详情，修的是移植错误，但它已不算完全未见过的数据。

## 局限（NOT_VERIFIED）
- 约十分之一的合成内容会漏掉，真实截图可能更差：ClearType 文字、复杂背景、图片里的文字都没有测过。
- 姓名、地址没有固定格式，规则找不到。
- 跨行内容、被切开太多的数字找不到。
- 出图自检只能说明这个识别器读不出，不能证明无法还原。遮挡的像素不含原文是另一回事，由 Rust 渲染和像素读回保证。
- 替换用内置字体，不会和原字体一样；渐变或图片背景上能看出色块。
- Windows 11、多显示器、缩放、HDR、真人使用。
