# Gate A candidate — Stage 01: decide whether and how to build ShareReady

> **SR-DEC-001 · 2026-10-14 · HUMAN CANDIDATE APPROVED / CLI GATE A PENDING**  
> This is a decision **candidate**, not a finalized ADR or a machine-validated `.decision/decision-card.md`. Stage 00 status: CONDITIONAL GO. Gate A status: **human candidate approved; de.py Gate A preview/token/confirm NOT RUN**. See [approval record](STAGE01_GATE_A_APPROVAL_RECORD.md).

- 日期：2026-10-14
- 结论：改后做（仅进行研究与产品定义，未经证据验收不开展 Rust 工程实现）
- 置信度及依据：中低；已知有实际截图隐私处理需求与成熟竞品，但没有同条件真人计时、遗漏率和留存数据。

## 目标

以可复核的用户任务和竞品证据，判断是否值得开发一款 Rust-first、本地处理、免费开源的“截图发送前检查工具”；产出明确的 PRD 与架构选择条件，允许否决项目。

## 成功标准

1. 建立至少 4 个直接替代方案（Redacted、ShareX、Redaction Tools、系统自带截图工具）的**逐任务**对照矩阵，记录版本、环境、出处、`DOCUMENTED/MEASURED/NOT_VERIFIED`，不将宣传页等同实测。
2. 为聊天记录、订单、技术求助、边界文字、JPEG 元数据定义至少 5 个**完全虚构**的测试样本，以及目标遮挡项、应保留项和导出检查判据；确认没有真实个人信息进入仓库。
3. 明确记录 10 名目标用户访谈与任务实测的招募方案、同意与匿名化方式、完整记录字段；只有实际参与后才可写 `MEASURED`，人数不足时只能标 `BLOCKED_BY_RECRUITMENT`，不允许补造。
4. 形成 Stage 01 PRD Draft：核心用户、JTBD、场景与状态、P0/P1/非目标、隐私边界、可量化差异化假设、产品退出条件，且对每一项不确定主张标出验证状态。
5. 比较 Rust+WASM/Leptos CSR、Rust 核心+Tauri 2、Rust 原生 Slint/egui 的用户路径、编译部署、兼容性与安全验证成本；仅给**条件性推荐**，不在 SPIKE 前冻结 UI 框架。

## 非目标

- 不在本决策阶段编写 Rust 图片处理逻辑、UI 代码、构建 CI、发布 APK/桌面安装包或上线网站。
- 不声称“所有个人信息已被识别”“绝对匿名”或“对现有工具形成了已验证优势”。
- 不对已有竞品进行无授权反编译；REA 只在合法且必要的黑盒场景作单独决策。
- 不将 `ShareReady` 直接视为已清除冲突的正式品牌；已存在同名及相似定位产品。
- 不绕过 deciding-and-executing Gate A、Gate B，也不以广泛 GitHub 写权限替代每次门禁审核。

## 候选路线与反方论证

| 路线 | 最强支持 | 最强反对 | 启动条件 |
| --- | --- | --- | --- |
| A：Rust/WASM 本地 Web 工具（推荐作为原型候选） | 链接即用，利于跨平台获取反馈，Rust 可共享核心像素模块 | 用户不一定愿意离开已有截图工作流；浏览器剪贴板受限制 | A1 成立；完成浏览器能力 SPIKE |
| B：Rust 核心 + Tauri 2 桌面工具 | 文件/热键/系统整合潜力更强，减少切换成本 | 安装与签名分发成本，macOS/Windows 支持负担 | 实测表明系统工作流集成是首要瓶颈 |
| C：Rust 原生 egui/Slint 桌面工具 | Rust 主导且原生应用边界清晰 | 图像编辑精细交互、复制与平台差异需额外实现 | UX 对原生工具框架有明确收益 |

建议优先验证 **A1**；A1 不成立时无需进行 Rust 技术 SPIKE。

## 最大风险

核心价值与已有工具高度重叠，且“截图高频”不等于“截图脱敏高频”。因此可能做成技术正确却无人常用的产品。第二风险是误导性隐私安全承诺及同名品牌冲突。
