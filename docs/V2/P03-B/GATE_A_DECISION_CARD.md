# 决策卡：SR-V2-03 B0 真机基线观察

- 日期：2026-10-17
- 结论：改后做（继续 egui/wgpu 候选方向；本卡只推进 B0 基线观察，产品修改与合同变更另行评审）
- 置信度及依据：中，Rust Core/Editor 和软件渲染窗口已有固定 SHA 的机器证据，但物理 GPU、多屏 DPI、完整键盘和 Narrator 尚未验证。

## 目标
在用户已确认可用的当前 Windows 电脑和双显示器上，为固定 Rust 原生样机形成可追溯的真实基线结果或明确缺口，先检验画布、DPI 和键盘路径，供下一批有界修复作决定。Gate A 仅确认观察方向、判据和暂停条件；测试命令、设备操作及输出位置在独立 Gate B 预览后才能执行。

## 成功标准
1. 待测源码固定为 main 的 94f7f419aee91faf6f846349d40a897d0d72d7d0，EXE SHA256 为 386200cc23ff8015258b655a6911c1993c8d08e8fef3e57ca826e9757fc76b9d；锁文件、五张合成输入和工作区差异均留身份记录，换版本后重新绑定。
2. 真实 Windows 会话记录实际 GPU/backend、双屏分辨率与 DPI、会话类型、操作者和窗口结果；设备枚举不代替样机实际使用的适配器证据。
3. G01/G02/G03/G08 的高风险任务取得真实执行状态或明确的实现/证据缺口；指针映射和输出像素分别取证，缺失功能不虚构为 PASS。
4. G01～G10 合同范围完整保留；尚不能执行的场景对应最小修改和复验条件，保存、缩放及剪贴板差异单独评审，不用 B0 观察结果替代全量验收。
5. V1 用户实现、五张金样本与已有文档保留；B0 不改产品代码、来源图片、用户既有文件或系统权限，不删除、不提交、不推送、不发布。可逆测试输出及设备/剪贴板操作须在 Gate B 明确范围。
6. 每批结果绑定源代码身份、EXE 和证据文件哈希，真实区分 PASS/FAIL/NOT_RUN 与限制；失败先分类，再提出下一项有界修复，不自行实施。

- 不执行 M01～M09 修改，不创建正式 apps/desktop，不升级依赖，不启动 iced，不迁移或删除 V1。
- 不开发 OCR/AI、账号、云服务、批量、图库、覆盖保存或其他新增产品功能。
- D02～D05 的物理缩放、仅新建保存、剪贴板格式和编辑保护仍是候选；本次确认不批准合同变更或相应实现。
- 不将当前 Windows 10、约 16GB 电脑的结果外推到 Windows 11 或 8GB 参考档，不以软件适配器代替物理 GPU。
- 不改显示设置、剪贴板、网络或系统权限来准备本次 Gate A；后续可逆设备操作需在 Gate B 中具体列出并由操作者执行，不扩大授权。
