# P03 A Windows 真机测试协议

版本 1.0。用途：Gate A/B 评审及后续操作者执行。所有 TC 用例本轮均 NOT_RUN，本文的步骤和预期不是实测结果。当前待测身份见 BASELINE.json；代码一旦修改，建立新的 SHA/工作区指纹与 EXE 哈希，并明确哪些旧证据仅供比较。

## 1 资源登记与执行条件

### 1.1 已有资源

用户确认当前 Windows 电脑及双显示器可用。只读设备查询为 Windows 10 build 19045、15.8 GiB RAM、Intel UHD 与 GTX 1650，同时有虚拟显示适配器。将这台电脑暂称 DEV-A，不能把设备枚举直接写成“GTX 1650 已渲染”。启动后的适配器记录才说明本次使用了什么。

现场必须补记：操作者、当地时间及 UTC、是否本地会话、两屏分辨率、每屏缩放、拓扑、实际后端/GPU/驱动、窗口所在屏、工具版本。双屏资源已确认，但混合 DPI 组合、Windows 11 和 8GB 参考档尚未验证。缺设备或无法测量就保留 NOT_RUN/NOT_VERIFIED，不用软件适配器代替。

### 1.2 可执行条件

先完成当前真实 Skill 的 Gate A/B，核验工作区和命令副作用。使用独立、空的测试目录及合成图片，不访问私人截图。允许写入的位置、临时 DPI 调整、剪贴板变化、窗口启动、网络观察和恢复方式都应出现在 Gate B 预览中。本协议不授权更改系统 ACL、安装驱动、改防火墙、填满磁盘或对外发送数据。

若 EXE 哈希不符、来源 SHA 不明、工件已过期且无可校验副本、出现无关产品改动或样本哈希不符，停止该次运行。每次修复后的 EXE 都是新待测对象，不能沿用旧 EXE 的验收。

### 1.3 首先观测的 B0 范围

只观察当前固定 EXE 的实际渲染设备、现有 T04 指针路径、100% 显示语义及键盘/Narrator 可达性。缺少 Fit、精确控件、测试轨迹或键盘创建时记为“实现/取证缺口”，可以记录已有路径的现象，但不能把用例改成只测试窗口能打开。B0 不要求在未实现功能上耗时反复尝试。

## 2 固定样本与像素判定

### 2.1 已存在并校验哈希的五张输入

使用 `docs/research/fixtures/` 中的 T01_CHAT、T02_ORDER、T03_SUPPORT、T04_EDGES 和 T05_JPEG_EXIF。各输入哈希、尺寸、遮挡和冻结输出 RGBA 哈希完整保存在 BASELINE.json。保留 T05 的 Rust JPEG 归一化锚点，不用 Pillow 的源 JPEG 解码差异重新定义真值。

G01 的 T04 为 2400×1600，输入 SHA256 为 `b50f6070f4704ef7753ba58493b8e629b51507723ac4c4c8ccff9b629461f83d`。四个冻结遮挡为：

| 区域 | 半开坐标 x0 y0 x1 y1 |
|---|---|
| 左上 | 15 12 950 90 |
| 右上 | 1550 12 2394 90 |
| 左下 | 8 1497 905 1595 |
| 右下 | 1490 1497 2398 1595 |

使用这四框时，最终解码 RGBA SHA256 必须为 `554f68cc5c99577fd621cb894d535a38c44565a347ef4e1e00bd89e4d04daafc`。PNG 文件本身编码哈希可以不同，需另外记录。遮挡色必须为 RGBA(17,24,39,255)，尺寸不能变化。

### 2.2 需要后续生成的补充样本

这些文件本轮未生成，哈希未填，不可标记已可用：

- F24：6000×4000、RGBA、不含私人内容；像素公式 R=x mod 256，G=y mod 256，B=((x div 64) XOR (y div 64)) mod 256，A=255。生成 PNG 后确认压缩大小不超过 25MiB，记录输入和 RGBA 哈希；若超限，调整测试方案须留记录，不能变成压缩输入超限测试却仍叫正常 24MP。
- FA：16×16 RGBA，包含 alpha 为 0、64、128、255 的四条色带，透明条带保留非零 RGB；用于分别观察 PNG 与系统图像格式的透明度行为。alpha=0 下 RGB 的规范化另记，未经 D04 确认不能要求目标应用保留隐藏 RGB 或擅自忽略差异。
- FN：非图片字节、截断 PNG/JPEG、25MiB+1 的受控文件、超 24MP 的小压缩图片；只在专用目录生成，不在仓库堆放大二进制，不使用攻击真实数据的样本。

样本生成与校验工具是后续 B0 准备或 M01 的明确任务，进入相应 Gate B 后执行；不能因为已有生成公式就标记准备完成。

### 2.3 三种不同的正确性证据

1. **指针映射**：独立记录物理指针、实际渲染图框及每点比例，按 `x=(pointerX-frameX)/frameWidth*sourceWidth` 等公式，左上 floor、右下 ceil 并钳位，推导期望区域。与 Editor 最终区域比较，不能只相信 GUI 自报 mask。
2. **像素输出**：独立解码来源 PNG，按已核对区域覆写 RGBA，逐像素比较输出的整张图片，包括未遮挡像素、尺寸、alpha；再检查 PNG 结构、CRC、无源元数据及无尾部载荷。
3. **冻结兼容**：在精确输入或键盘微调得到上述四框后，直接比较冻结 T04 RGBA 哈希；五张金样本在其原有 Linux CI 链路继续验证。

Fit 下屏幕像素可能无法直接表示每个来源像素端点，因此不得要求操作者盲拖得到任意精确整数矩形。物理拖拽先验证实际事件推导；冻结四框另用精确调整复现。两项都需要，不能用调整后的结果掩盖拖拽偏移，也不能以用户手误自动判坐标引擎失败。

当前缺少独立指针轨迹/图框记录与文件 oracle，相关用例尚不能闭合。这是 M01 的前置缺口，而不是允许跳过证据。

## 3 G01 画布坐标与真实成品

### TC-G01-01 四角与缩放

前置：T04 哈希通过，Fit/100%/200% 及精确区域调整可用，M01 证据工具已验证。每个缩放状态从干净文档开始，人工在四角绘制、核对指针映射，再精确调整到四个冻结框。记录图框、比例、实际 mask，点击检查成品，另存新 PNG。

预期：指针推导与 Editor 区域一致；精确四框导出尺寸 2400×1600，RGBA 等于冻结哈希；未遮挡区域与归一来源一致。至少保存三组输出、指针与矩形记录、成品视图截图及独立比较报告。只有源码自检或缩略图截图不满足通过条件。

### TC-G01-02 负向 贴边与小区域

在四个方向反向绘制，穿过图像边界，测试角上 1px 和 1px 窄条。每次记录来源区域，核对向外取整、钳位、不翻转和有效范围。导出与独立合成相同。零面积或完全无效区域不能变成可交付的原图。若物理精度不足，用键盘微调完成 1px，并保留鼠标覆盖部分的独立结论。

### TC-G01-03 空遮挡与复核身份

新建文档不画框尝试 Review/Copy/Save，预期拒绝或禁用且无输出。绘制后检查成品，核对实际 PNG 来源、尺寸及哈希，成品视图不得显示选择手柄或工作预览并冒称成品。返回编辑并修改后交付必须要求新成品；回退导出原图立即判 FAIL。

## 4 G02 八方向与历史

### TC-G02-01 八方向精确调整

先建立来源区域 [100,100,200,200]。每个手柄单独从这一初始框开始，按如下来源像素改动；用原生指针完成可操作性，再用 1px 控件确认精度，每次独立核对输出。

| 手柄 | dx dy | 期望 x0 y0 x1 y1 |
|---|---|---|
| NW | -1 -1 | 99 99 200 200 |
| N | 0 -1 | 100 99 200 200 |
| NE | 1 -1 | 100 99 201 200 |
| W | -1 0 | 99 100 200 200 |
| E | 1 0 | 100 100 201 200 |
| SW | -1 1 | 99 100 200 201 |
| S | 0 1 | 100 100 200 201 |
| SE | 1 1 | 100 100 201 201 |

对边不动，不产生翻转/零尺寸。移动 (+1,-1) 后期望 [101,99,201,199]，宽高不变。额外测试 1px 框、贴边和可见命中提示；手柄无法操作或方向不明要记录，不用侧栏按钮替代鼠标手柄的全部验收。

### TC-G02-02 键盘和取消

全程不用鼠标：导入、创建、选择、移动 1px、调整、删除与撤销、复核、保存。活动手势按 Esc 后不提交；文本框输入、Delete 和粘贴遵循焦点。没有创建/移动入口就标为实现缺口，不将只按 Z/Y/Delete 视为完成核心任务。

### TC-G02-03 历史合并

一次拖动中移动至少五次，松开只产生一次可撤销动作。撤销恢复起点，重做恢复终点；新动作清除 redo；取消不提交。每次真实变更后旧 PNG 失效，撤销/重做也不能复活旧工件。附版本与区域序列、操作录像和输出像素比较。

## 5 G03 DPI 与双显示器

### TC-G03-01 单屏四种比例

在至少一块物理屏上分别配置并记录 100/125/150/200%，每种比例执行 TC-G01-01 的三种缩放和四角；对 1px 用例再抽取每屏可表示的精确路径。临时改系统缩放由操作者进行，保存原值并在会话后恢复，不能由代理无提示改设置。

建议 D02 的 100% 为一来源像素对应一物理像素，200% 对应 2×2 物理像素。比例需通过截图的像素尺寸和实际图框测量证明，不能凭滑块数值或 OS 设置推断。每个缩放记录输入/输出、图框、像素比例和差异报告。

### TC-G03-02 混合 DPI 搬屏

至少执行 100%↔125% 和 150%↔200% 两组混合比例，两方向搬移，分别在 Fit/100%/200% 重做四角路径。若设备不支持组合或需要重新登录，记录限制并先评审替代矩阵；不得悄悄缩成同 DPI 两屏。

搬屏前后来源区域和 PNG 像素保持一致，比例变化后指针仍对齐。记录两个显示器参数和窗口实际所在屏；若会话受 GameViewer/远程虚拟屏影响，单列结果，不替代本地物理双屏结论。原生窗口有一次成功不是该项通过。

## 6 G04 24MP 与资源

### TC-G04-01 图像显示与细节

生成并固定 F24，启动后记录真实 adapter backend/type/name。导入 6000×4000 图，在 Fit/100%/200% 移到四角，绘制和调整，复核原像素细节并另存。确认使用的是实际 PNG 的可见原像素区域，不是把 2048px 缩略纹理放大。

预期全尺寸输出和区域像素正确，纹理尺寸不超设备限额，无崩溃或无响应。Dx12/Cpu 另列兼容记录，不能满足物理 GPU 的结论；有 Intel/NVIDIA 硬件名也仍需观测本次 adapter。

### TC-G04-02 资源与耗时

冷启动 5 次，交互至少 30 个样本，导入/复核循环 20 轮。记录首屏可操作时间、生成时间、拖动/平移帧时中位数/P95/最大值、进程峰值工作集和资源趋势；GPU 资源工具取不到就写未测，不能用 RSS 代替全部 GPU 内存。

总方案提出的 100ms 反馈、33.3ms P95、3s 导入、5s 生成、1GiB 工作集只是候选预算。先采基线，再独立确认设备和阈值，未冻结时本项只能 MEASURED / ACCEPTANCE_PENDING，不能标性能 PASS。探针 wall_ms 是窗口生命周期耗时，不能作为帧时。

### TC-G04-03 边界与重复操作

分别导入 FN 的输入字节超限、像素超限、截断与错误格式。观察平台读取分配、拒绝与当前文档保留；20 轮重复导入/复核后记录峰值及趋势。不要将分配器暂存自动定性为泄漏，也不要仅因最终拒绝就忽略之前的无界读取。

## 7 G05 原生输入与替换

### TC-G05-01 文件选择

通过真正 rfd 系统对话框选择 T01 PNG 与 T05 JPEG，验证方向、尺寸、编码输出及取消。对话框取消不换图、不清除历史。保存对话框与图片选择分别测试，不能用 DOM 文件输入代替。

### TC-G05-02 Explorer 拖放

从真正 Explorer 将 T04 拖入编辑窗口，再拖入 T05。记录实际鼠标和窗口结果，验证与文件选择归一后一致。多文件拖入的策略需明确：建议拒绝多文件并说明单图范围；当前代码逐个加载不能当作已批准的多图策略。操作取消或不支持格式保留旧文档。

### TC-G05-03 错误与取消

在已有多框编辑的文档中导入非图片、截断、超限或不可读测试文件；预期错误可解释，源图、区域、历史与当前可用结果按合同保留。不可读位置由操作者选择既有受限目录，或使用受控适配层，禁止为测例修改系统 ACL。

### TC-G05-04 换图 关闭与清空

已有编辑时通过文件、拖放和后续粘贴分别请求新图，先取消丢弃再确认丢弃。取消保留所有编辑，确认才换文档并废弃旧输出。关闭取消回到原任务；清空可撤销且不复活旧 PNG。当前没有相应确认入口时记实现缺口，不直接试用私人图片。

## 8 G06 系统图片剪贴板

### TC-G06-01 粘贴导入

从 Paint 或另一可记录格式的应用复制 T01/FA，在非文本焦点粘贴导入；无图片、文本、超像素图及已有编辑的替换取消分别测试。记录实际系统格式和解码后的 RGBA，不能用预存 PNG 路径或模拟事件代替图片粘贴。

### TC-G06-02 不透明图像跨应用回贴

以 T04 四个冻结框生成当前成品，点击复制图像，分别粘贴到 Paint 和第二个真实程序。记录两程序名称、版本、粘贴后的图像尺寸与像素读回方式。目标程序另存可能转码，须记录格式；使用无损读回才能比较原图像素。

两个读回均应 2400×1600，与当前成品不透明 RGBA 一致。源 PNG 字节哈希不要求等于 DIB/目标应用文件哈希。任何读回失败、未知转换或不可取得像素均不算通过，不能以复制 API 成功替代。

### TC-G06-03 透明度与格式差异

使用 FA 遮挡部分区域后交付到两个程序，记录 alpha、透明像素 RGB 和目标格式的实际行为。若格式丢 alpha 或程序扁平化，明确列出差异并重审 D04；未确认的有损策略不能豁免像素要求。PNG 文件保存仍须保留其约定 RGBA，两个输出渠道分别验收。

### TC-G06-04 占用与失败恢复

通过测试适配层或明确记录的短时剪贴板占用使复制失败。预期提示真实失败、不报成功、编辑保留，可重试或另存 PNG。测试会改变系统剪贴板，操作者先保存需要的内容；不承诺自动恢复所有原剪贴板格式，也不执行无上限自动重试。

## 9 G07 文件交付

### TC-G07-01 新路径与取消

将当前成品保存至测试目录的新路径，核对文件、RGBA、PNG 结构及成功文案。另一次选择取消，目录快照前后无新增输出，当前文档和可复核成品仍可用。

### TC-G07-02 同名与源路径

测试已有目标、来源路径以及在选路径后由受控协作者创建同名文件的竞争。D03 若采用仅新建策略，预期明确拒绝，既有/来源文件哈希不变。未批准 D03 时记录 PRODUCT_DECISION_PENDING，不能擅自改原合同的覆盖预期。

### TC-G07-03 写入故障

在受控适配层注入短写、磁盘满、权限拒绝或同步失败；真实文件错误只使用操作者指定的隔离目录。预期未报成功，原文件不变，不留下冒充成功的最终 PNG。残留与清理需可追溯，测试不填满系统盘、不改权限、不批量删除。

### TC-G07-04 重试与过期

故障后换新路径重试，应保存当前成品一次；在可控延迟期间修改/替图，旧返回不能显示为新文档成功。已发生的外部写入需如实记录，不能假称作废令牌已撤销磁盘副作用。

## 10 G08 中文 键盘与 Narrator

### TC-G08-01 中文与 IME

在测试目录使用中文及空格文件名，通过原生对话框用中文输入法输入或选择，检查应用标签、文件名和错误无缺字。egui 与系统对话框分别记录。没有产品用途的 egui 文本输入框时不新增演示框来制造 IME PASS；若新增像素数值输入，验证 IME 不破坏数值规则及快捷键。

### TC-G08-02 全键盘核心任务

从启动开始不使用鼠标，完成导入、创建有效框、选中、移动/调整、撤销重做、复核、复制或保存。记录 Tab 序列、可见焦点、快捷键、Esc 与弹窗返回。只能聚焦按钮、不能创建区域时不得通过。输入焦点下的 Delete/撤销/粘贴不误改画布。

### TC-G08-03 Narrator

使用 Windows Narrator 完成同一任务，记录工具名、选中、区域编号和尺寸、忙碌、错误及交付是否正确读出。缺语义、焦点丢失或任务无法完成分别记录。机器扫描和 AccessKit feature 不能替代真实操作者结果。使用的辅助技术与版本写入记录。

## 11 G09 当前版本与延迟结果

### TC-G09-01 编辑使成品失效

检查成品后分别移动、调整、新绘制、删除、清空、撤销及重做，尝试立即复制/保存。当前版本必须重新生成，旧字节不能通过 bytes_for 读取为新结果。记录文档/版本/操作序列，特别覆盖新框绘制起点与已有框手势起点，取消也不伪称保留旧审批。

### TC-G09-02 换图与等待结果

由受控适配层持有旧 Review/Save/Copy 返回，换成另一图或撤销后再释放旧返回。预期拒绝旧身份，不出现当前文档成功。同步 GUI 无法在等待时换图则标明该路径不可人工触发，并分别报告领域注入与真实 GUI 集成范围，不能虚构鼠标竞态。

### TC-G09-03 重复完成与错误顺序
