## 2 Gate A 决策卡候选 SR P03 D01

### 问题与建议结论

当前 Rust Editor 和 egui 样机已有实现，Windows CI 软件渲染窗口通过；真实设备与完整任务尚未验证。建议“改后做”：继续 egui/wgpu 候选路线，先观察当前基线的 H01，再在批准的小批次内修复必要缺口。暂不冻结 GUI，不创建正式桌面 Workspace，不删除 V1。

### 目标与编号成功标准

本卡先确认有限验证方向，下一 Gate B 只选 B0。标准 1～6 是后续计划 covers 的编号，避免与历史研究 A1 混淆。

1. 待测源 SHA、EXE、锁文件、输入样本和工作区差异均可追溯，换版本后重新绑定证据。
2. 真实 Windows 会话中记录实际 GPU/backend、双屏与 DPI、操作者和窗口结果，不将设备枚举当程序使用证明。
3. G01/G02/G03/G08 的高风险任务有真实状态或明确实现/证据缺口；指针映射与像素输出独立取证。
4. G01～G10 范围保持完整，尚不能执行的项对应最小修改和复验条件；保存/复制等差异显式评审。
5. V1 用户实现、五张金样本和已有文档保留；本批不发生代码修改、删除、推送或发布。
6. 每批输出有哈希和原始证据，记录 PASS/FAIL/NOT_RUN 与限制；失败分类后只修必要范围。

### 非目标

OCR/AI、账户/网络服务、批量、图库、正式 GUI 迁移、框架升级、第二 GUI POC、覆盖保存实现、产品发布，以及删除历史工程均不在 B0。Windows 11 与 8GB 档需后续设备补测，当前不宣称已覆盖。

### 方案比较

| 方案 | 可验证收益 | 代价与主要风险 | 建议 |
|---|---|---|---|
| 先观察基线 再有界补齐 egui | 复用已有 Rust 状态与样机，先得真实设备证据 | 已知缺口会阻止某些场景通过，需要修复后复验 | 采用 |
| 直接扩建完整工作台 | 较快形成更多可见功能 | 可能在 DPI/键盘假设失败前投入过多 | 暂缓 |
| 立即换 iced | 可能解决尚未定位的框架问题 | 没有物理失败证据，重新付出同题验证成本 | 尚无触发依据 |

### 关键假设与止损

H01：egui 能满足精确画布、混合 DPI 和完整键盘/Narrator P0。当前 HYPOTHESIS，优先观测。G04 的显示资源与 G06 的格式一致性为后续关键假设，不用 CI 软件窗口代证。

- 触发状态：出现原图像素泄露、源文件改变、旧成品假成功、无提示丢编辑，或 H01 关键失败经一轮有界修复仍不能满足。
- 复核期限：建议 2026年10月31日；未开工只重排，不据此判框架失败。
- 动作：停止受影响路径，保存合成证据，区分环境/实现/工具/方向；有界修复仍失败再回到 Gate A，不能自动启动 iced。

### 命令与副作用预览输入

只读命令候选：`git status --short --branch`、`git rev-parse HEAD`、对 BASELINE 所列来源与 EXE 执行 SHA256 核验。命令型验证候选为：

```powershell
cargo test --workspace --locked
cargo check --workspace --all-targets --locked
& $P03TestExe --self-test
& $P03TestExe --renderer wgpu --smoke-window
```

`P03TestExe` 必须在正式 Gate B 前解析为真实绝对路径，并核对 SHA256 为本包固定值，不能批准任意可替换路径。正式预览还需锁定工具链、独立输出目录、实际 PowerShell/日志捕获命令和操作超时；这些现场绑定项在本材料中尚未确定，所以本文件不能直接作为完整 verify_cmd 执行。

Cargo 可能访问依赖源、更新缓存并写 target，已有代码中的测试会读取合成样本；`--locked` 不等于无网络。EXE 自检会解码内置 T04；wgpu smoke 启动真实窗口并请求关闭，写 stdout/stderr。不得把探针总体耗时当帧时。

本批不运行现有三路 PowerShell 探针：它会在输出目录删除同名旧日志，且输出会读环境中的 GITHUB_SHA。需要三路比较时另将空目录、参数、环境绑定、日志覆盖与子进程超时处理写入 Gate B，不能直接拿 CI 命令作用于已有目录。B0 用受控单路启动先观察 wgpu 主路径。

人工 B0.2/B0.4 会产生窗口、截图和合成输出，可能临时改变 DPI 或剪贴板；操作者按批准范围操作并恢复。未经具体预览，不执行该部分，也不由自动化代签人类结果。

### 执行前必须绑定的参数

- genuine Skill 的真实位置、版本及现有机器状态；不能假定旧 Stage 01 已批准新任务。
- Windows 构建所用工具链、P03TestExe 的实际路径与哈希、全新证据目录。
- 操作者、两屏参数、会话类型及是否允许临时缩放变更。
- 回归的实际 code fingerprint；源文件有新改动时重新固定，而不是沿用旧 EXE。

这些是正式预览的输入参数，不影响 P03 A 文档完成；未绑定前不能标记 Gate B READY/PASS。

## 4 需要保留的评审独立性

本包由同一代理根据源码、API 与工件编制，属于自查与事实核对，尚无独立审查者签署。后续交付审查应读取最终产物和成功标准，分别确认源码、机器结果、人工操作与安全边界。文件哈希完整不能代替这些判断。

当前可评审的是方向、合同、测试协议及最小范围。真实 A 预览确认和真实 B 预览确认必须分开；本轮用户的 P03 A 指令不被记为对尚未出现的 token 的确认。
