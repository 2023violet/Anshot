# P03-D：有界导入与编辑保留

本批在原生样机现有文件、拖放和关闭路径上实现 M05。前批缩放、输入与独立 PNG 检查的精确历史证据保留在 [P03-C](../P03-C/README.md)。仍在 `main` 本地开发，未替换 V1、升级依赖、修改冻结样本或发布。

## 产品行为

- 文件先检查长度，再通过受限 Reader 读取，最多消费 Core 的 25 MiB 上限加一个判定字节。文件在长度检查后增长也会被拒绝；短读和读取中断不会产生部分候选。
- Rust Core 解码与显示准备成功后，才把图片作为候选。失败时保留原源字节、区域、DocumentId/Revision、撤销历史、已经生成的 PNG 和仍有效的操作凭证。
- 文件选择和单图拖入共用入口。多图拖入在读取任何一张之前拒绝；合成追踪模式仍禁止私人图片导入。
- 当前文档只要有编辑/Redo 历史或活动手势，换图和关闭就进入同一个保留/放弃确认。PNG 导出不等于保存了可编辑历史，因此导出后仍有这一保护。取消、Esc 或对话框外点击都保留当前文档；只有选择 `Discard edits` 才替换候选或发出关闭命令。
- 活动手势先取消未提交预览，再显示确认，保留已经提交的遮挡和历史。取消预览后再次点击关闭，仍不能绕过已有确认框。一个确认未处理时，不继续读取另一候选，也不执行画布编辑、Review、Copy 或 Save。
- 清空遮挡继续采用已有可撤销行为。没有编辑历史的文档可以直接换图或关闭。

这是 D05 的本批选择：用最小候选与显式放弃确认保留编辑；不引入编辑工程自动保存格式。设计和真实 Gate A/B 由代理按[已生效授权](../../governance/AUTONOMOUS_LOCAL_DEVELOPMENT.md)记录确认，不称为用户逐 token 评审。

## 验证

当前机器结果见 [RESULTS.json](RESULTS.json)，独立审查见 [INDEPENDENT_REVIEW.md](INDEPENDENT_REVIEW.md)。原始 genuine 工作区为 `target/workflows/p03-d`。测试工具复用既有 `tests/native_oracle/run_native_checks.py`，所以新的唯一构建目录仍位于 `target/p03-c-evidence/native-<时间>/`；必须按本批 report、build ID、源码及 EXE 哈希识别，不能以目录前缀判断版本。

| 检查 | 范围 |
|---|---|
| 原生应用 25 项测试 | 有界 Reader、失败保留、有效候选等待、取消/明确放弃、Redo、活动手势、多图、模态 Esc、重复关闭；同时保留前批缩放和输入回归 |
| 主 workspace 34 项测试 | Core 5、codec 9、Editor 18、集成 2；Rust 图片与过期操作规则保持 |
| 新 EXE | 锁定构建、自检文件和实际 DX12 / GTX 1650 窗口 Review 文件，均与冻结 T04 及独立全图 oracle 对应 |
| 外部 PNG 检查器 | 19 项独立反例测试的前批结果绑定原检查器字节；本批未改该检查器；新 EXE 的文件另行实际检查 |

自动 smoke 只操作内置合成图片，程序化结束测试进程会明确允许它自己的关闭。它证明窗口生命周期与输出文件，不证明用户点击过放弃按钮，也不证明真实系统文件选择、Explorer 拖放、跨屏鼠标或人类可用性。本批关闭命令测试使用真实 egui `RawInput::ViewportEvent::Close` 和 `ViewportCommand::CancelClose/Close`，与真实 Windows 外壳操作分别标记。

## 仍保留的完整产品缺口

G05 的机器保护路径已有实现；实际 Windows 对话框、Explorer 拖放和普通用户取消/恢复仍需实机观察。G06 的有界图片粘贴和跨应用 alpha、G07 的完整新文件写入/失败清理与重试、G04 的 24MP/性能、G08 的中文/IME/Narrator、G10 的离线包/网络/许可仍开放。混合 DPI 与实际显示像素也没有因本批测试而通过。

下一批优先封闭 M06 保存失败与无覆盖交付边界，再接入 M04 的受限剪贴板导入。不得以现有直接 `create_new + write_all` 当作完整保存协议，也不得从总验收表删除未实现能力。
