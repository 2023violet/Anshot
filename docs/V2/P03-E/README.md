# P03-E：Windows 新 PNG 保存与失败保留

本批完成 M06-A 的本地实现和机器验证：原生样机只另存新 PNG，拒绝覆盖，保存失败或取消后保留当前成品和编辑，允许重试。前批导入和关闭保护保留在 [P03-D](../P03-D/README.md)。完整 M06、G01～G10 与产品交付仍开放。

## 当前行为与选择

- 文件选择之后，先校验 Save 凭证的类型与版本，再接触文件系统。过期回调不能写文件、修改新文档状态或清除新的 Review；取消、位置错误和同名错误均保留 PNG、修订与历史。
- 新平台 crate 使用 `create_new` 建立独占文件句柄，创建时即设置关闭回滚。完整写入并同步成功后，才用同一借用句柄取消回滚；句柄释放之后返回成功。失败不按文件路径删除，不覆盖既有文件。
- 当前 Windows / NTFS 测试覆盖部分写入、同步/提交错误注入、同名竞争与真实子进程提前退出。文件创建至提交期间，目录中可能看见不可正常打开的条目；没有承诺目录条目原子可见性或断电事务。
- 真实反例发现 NTFS 的 `文件名:数据流` 可绕过仅使用 `create_new` 的保护。保存入口现提前拒绝 ADS、设备及非普通文件命名空间，打开后还检查文件类型。反例只操作自建合成文件；设备名称测试仅调用校验函数。
- D03 选择只保存新文件，已有目标明确拒绝并提示换名。这与 V1 的覆盖能力存在迁移差异，不记为覆盖功能等价。
- Win32 调用限定在薄平台 crate；GUI 和 Editor 保留现有 `forbid(unsafe_code)`。Core 未改且未新增 unsafe；Core 原本没有该 forbid 属性，决策材料中“现有 lint”不得解释为它原本具有该属性。像素变换和 PNG 编码仍在 Rust Core/Editor。
- 复用原生依赖图中已有的 windows-sys 0.61.2。根锁只增加必要平台包、windows-sys/windows-link，原生锁只增加平台包及依赖边；既有包版本与校验和未升级。Windows CI 新增平台路径触发与独立平台测试命令，远程 CI 尚未执行。
