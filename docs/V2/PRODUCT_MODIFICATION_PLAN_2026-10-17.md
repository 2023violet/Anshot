# ShareReady V2 产品修改与优化总方案

版本 1.0　日期 2026年10月17日　文档编号 SR PLAN 001

适用对象：产品负责人、Rust 开发者、测试与审查人员。

本方案建议继续完成 Rust 原生迁移，首先解决真实 Windows 设备上的画布、输入、成品复核与系统交付问题，再进行界面完善、专项验证和旧工程减重。现有 V1.3 保留为用户版本及迁移对照，原生样机通过验收后才逐步成为正式实现。

本方案是后续修改的评审依据。本文中的新设计、任务、性能预算及排期均为建议，尚未构成实施授权，也不替代项目 Gate A、Gate B、独立审查及发布批准。编制基线为 main 的 `94f7f419aee91faf6f846349d40a897d0d72d7d0`；实施时必须重新核对 HEAD 和未提交改动。

## 1 方案结论与修改顺序

### 1.1 最终交付目标

交付一款 Windows 优先、由 Rust 主导的单图片隐私遮挡工具。用户通过文件、拖放或剪贴板导入 PNG/JPEG，精确调整实心遮挡，查看实际生成的 PNG，再复制图像或另存为新文件。图片处理留在本机，应用无需账号、云服务或遥测。

图像处理、编辑规则、撤销重做、成品版本与操作结果由同一套 Rust 实现负责。Windows 正式运行链路以 Rust 原生应用为目标，取消对自编 JavaScript、C#、WebView2 和 .NET 宿主的依赖；操作系统组件及第三方底层依赖不以语言纯度为改造目标。

### 1.2 推荐的执行顺序

1. 核对 V2-03 验收合同与样机的差距，用真实 Windows 设备检验最可能推翻 GUI 路线的条件。
2. 以小步修改补齐原生导入、坐标、键盘及复核能力，完成 egui 的正式选型判断。
3. 实现稳定的 Windows 平台适配及完整 Rust 工作台，保持 Core 和 Editor 的单一业务事实来源。
4. 验证导出、保存、剪贴板、错误恢复与版本一致性，完成性能、安全及无障碍专项。
5. 在功能等价、回退可用、独立审查通过后切换用户入口，再按批准清单减重并形成交付候选。

### 1.3 近期应避免的投入

暂不扩展 AI/OCR、自动隐私检测、模糊与马赛克安全模式、账号、云同步、图库、批量处理、PDF/视频、社交发布、插件平台和跨平台交付。裁剪、颜色自定义、主题系统、自动更新也不进入本轮必做范围。Rust 比例仅作统计，不能成为删除测试、扩大模块或改写稳定代码的理由。

### 1.4 优先级与范围冻结

| 优先级 | 本轮对应内容 | 处理规则 |
|---|---|---|
| P0 必须完成 | 像素与版本正确、三入口、真实复核与交付、编辑保护、核心键盘及可访问性、支持设备边界 | 任一必需项失败阻断原生切换 |
| P1 体验完善 | 次要快捷键、细节对齐、较低频帮助及不影响任务的视觉调整 | P0 稳定后处理；未完成列明限制 |
| P2 后续候选 | 裁剪、主题、自定义颜色与更多平台 | 本轮不排期；有实际任务证据再评审 |

中文缺字、核心按钮不可达、复核细节不可见等妨碍任务的问题属于 P0，不能降为视觉打磨。安全阻断项不接受通过隐藏入口或放宽测试来消除。

## 3 产品定位与成功标准

### 3.1 产品服务的任务

优先服务普通 Windows 用户分享单张截图前的手动遮挡任务。常见图片包括聊天、订单、客服和软件界面。用户不需要先了解像素坐标、图像编码或 Rust；界面应让其看懂当前图片、已遮挡区域、正在检查的成品和真实交付结果。

产品只保证实现并验证明确范围内的像素替换与输出行为。用户仍负责识别未框选内容，不承诺自动发现全部隐私、不可推断身份或任何特定监管合规。

### 3.2 编号成功标准

| 编号 | V2 完成后应观察到的结果 | 验证方式 |
|---|---|---|
| S01 | Windows 产品由 Rust 原生应用运行 | 干净系统启动、依赖清单和包内检查 |
| S02 | 文件、真实拖放、图片粘贴三入口可用且错误不丢编辑 | Windows 操作、输入格式及失败回归 |
| S03 | 绘制、移动、八向调整、1px、历史和坐标精确一致 | Rust 测试加原生操作及导出像素对照 |
| S04 | 复核实际 PNG，编辑后旧成品不可复制或保存 | 成品解码、版本令牌和工作流反例 |
| S05 | 导出实心像素、尺寸、方向及元数据满足合同 | 五张金样本与异常图片、PNG 结构检查 |
| S06 | 保存和复制报告真实结果，失败可恢复 | 文件哈希、故障注入和两应用回贴 |
| S07 | 指定设备的 24MP、DPI、多屏与性能预算通过 | 设备实测、资源曲线和像素对照 |
| S08 | 中文可读，全键盘与 Narrator 完成核心任务 | 人工任务记录、焦点及语义检查 |
| S09 | 本地处理声明有网络、日志及依赖证据支持 | 指定场景观测和独立审查 |
| S10 | 旧路径退出有回退依据，候选包可追溯和复建 | 迁移矩阵、保存工件、构建记录及审批 |

### 3.3 成功标准的使用规则

每个实施任务必须引用 S 编号和对应 F/G/B 测试项。部分通过不能汇总成整体完成；例如源码调用剪贴板成功只覆盖调用结果，不覆盖 Paint 回贴像素。工程验收和真人体验研究分别记录，现有需求研究 A1 未验证状态继续保留。

## 4 架构方向与决策候选

### 4.1 三条路线的取舍

| 路线 | 适用条件 | 主要成本 | 本方案建议 |
|---|---|---|---|
| 继续 egui 原生路线 | 现有样机能满足画布、输入及无障碍 P0 | 实机验证、字体、精确画布和组件完善 | 首选，先取得关键证据 |
| 触发后评估 iced | egui 关键 P0 经有界修复后仍失败 | 同题 POC、界面重做与重新验收 | 作为条件式备选 |
| 保留现有混合架构 | 原生路线不满足可用性、安全或资源要求 | 继续维护 JS/C# 边界 | 作为回退，暂停原生切换 |

现有 DX12 软件渲染成功支持继续评估 egui，但不足以冻结选型。glow 在 CI VM 的失败也不足以要求换框架。未来若提出其他路线，应说明解决了哪个已测问题，并重新评审，不扩大本轮比较范围。

### 4.2 决策卡候选 SR D01

建议结论为“改后做”：保留既有 Core/Editor 和 V1 基线，完善原生样机的必要能力，并在实机上决定是否进入正式桌面工作台开发。最大风险是原生画布与无障碍未满足 P0，最缺的证据是真实设备任务和系统交付结果。

| 假设 | 当前状态 | 证伪方法 |
|---|---|---|
| H01 egui 能满足精确画布和 Windows 键盘无障碍 | HYPOTHESIS | G01/G02/G03/G08 真机任务 |
| H02 当前显示策略可支撑 24MP 可用性 | HYPOTHESIS | G04 内存、帧时、原像素复核 |
| H03 Rust 平台能力能达到现有输入输出完整性 | 部分源码存在，NOT_VERIFIED | G05/G06/G07/G09 故障与回贴 |
| H04 单图片工具的范围能保持小型工程 | 规划假设 | 阶段范围和依赖清单复核 |

H01 是优先验证的架构假设。第一次设备验证应同时触及精确画布和键盘路径，而不是先投入大规模视觉组件开发。若失败，最多进行一轮明确范围的修复与复验，仍失败再评估 iced。

### 4.3 暂停与重审条件

任何原图泄露、旧成品误用、静默丢失编辑或覆盖源图的问题都阻断原生切换。关键 P0 在一轮修复后仍失败则返回方向评审。建议首次进度复核日期为 2026年10月31日；若届时尚未开工，只更新排程，不能据此判 GUI 技术失败。正式 Gate A 需确认实机验证期限和资源负责人。

## 5 产品信息架构与界面原则

### 5.1 一个窗口完成一个任务

保留单工作区。顶部集中导入、撤销重做和检查成品；中央画布占主要面积；工具区只保留遮挡、选择和平移；侧栏展示尺寸、遮挡区域及当前选区；底部展示缩放和操作状态。避免增加仪表盘、项目列表和多级设置。

启动进入真实空状态，提供选择图片、拖放和粘贴说明。合成 T04 只用于测试模式，正式应用不默认打开演示图。编辑状态与成品复核状态在标题、操作区和画面上都应明确可辨，复核默认不并排显示原图。

### 5.2 小窗口与高 DPI

以 1440×900 和 1024×768 为主要布局检查点，800px 宽窗口用于检查降级布局。侧栏可折叠，核心操作不得因窗口变小而无法访问。布局单位使用 GUI 逻辑坐标，输出始终使用来源像素；100% 显示的物理像素语义须在第 10 章实现并测试。

### 5.3 视觉与中文

继承已有浅色中性工作台和选中强调色方向，令画布成为主体。统一按钮、工具切换、区域列表、焦点、禁用、忙碌和错误状态。主要操作目标建议不少于 40 个逻辑像素，既有 44px 目标在桌面布局中实测确认。颜色不承担唯一状态表达。

中文界面先覆盖导入、编辑、复核、保存、复制和错误。检查 egui 默认字体的实际中文覆盖，使用经许可核实的本地字体方案，不从 CDN 加载。字体文件、授权及离线结果必须入证据清单。暂不开发完整主题及多语言管理系统。

## 6 用户流程与状态合同

### 6.1 正常流程

导入图片后显示方向归一的图像和原始尺寸。用户绘制遮挡，选中后移动或八向调整，可通过区域列表和键盘精确修改。点击“检查成品”生成新 PNG，成功后进入成品视图；用户检查后复制图像或保存新 PNG，界面只报告实际完成的交付。

| 状态 | 允许的主要动作 | 必须保持的条件 |
|---|---|---|
| EMPTY | 导入 | 不可生成或交付成品 |
| LOADING | 取消、等待 | 导入失败保留上一文档 |
| EDITING | 遮挡、历史、缩放、检查 | 修改立即废弃旧成品和交付令牌 |
| GENERATING | 等待、取消或版本作废 | 失败拒绝交付，不输出原图 |
| REVIEW_READY | 原像素查看、复制、另存、返回 | 显示当前版本真实 PNG |
| DELIVERING | 等待系统结果 | 成功绑定文档、版本和操作 |
| ERROR | 重试、返回、另存替代 | 保留有效源图和编辑 |

状态名是本方案的界面概念，不要求逐字替换现有 Editor 枚举。GUI 状态不能成为绕过 Editor 校验的第二套输出规则。

### 6.2 需要显式确认的用户操作

已有编辑时换图、粘贴新图、拖入新图及关闭窗口，应提供保留当前编辑或放弃的明确选择。文件选择器取消不应触发确认或清空状态。清空遮挡采用可取消确认或明确可撤销方案，在工作台规格中统一，不增加自动保存历史。

### 6.3 复核与交付语义

Editor 的 reviewed 仅表示当前 PNG 已生成并被应用接受，不代表人已经看过所有细节。GUI 进入复核后提供明确的检查提示及交付按钮；若需要用户确认检查完成，应使用独立的界面状态，不伪装成算法识别结果。文案使用“已遮挡 N 处，请检查未遮挡内容”，不显示隐私安全评分。

## 7 Rust 工程与职责边界

### 7.1 目标结构

```text
Cargo.toml                    根 Workspace
Cargo.lock                    正式产品锁文件
rust-toolchain.toml            验证后固定工具链
crates/shareready-core         解码 方向 像素与新 PNG
crates/shareready-editor       文档 命令 历史 版本与交付令牌
apps/desktop                  正式 Rust 桌面应用 计划新增
  src/canvas                  显示 命中 手势与视口
  src/ui                      工作台与可访问组件
  src/platform                文件 对话框 剪贴板与设备信息
poc/native-egui               选型证据和样机 迁移期保留
tests/golden                  冻结行为真值
docs/V2                       迁移合同与阶段证据
```

以上是目标布局，不表示目录已经存在。进入正式桌面阶段再创建 apps/desktop，避免同时维护两套正式 GUI。平台能力先放应用内部模块，只有出现独立复用需求才考虑新 crate。

### 7.2 数据与调用关系

GUI 提交操作意图给 Editor；Editor 决定遮挡、历史、版本及输出有效性；Core 接收来源字节和遮挡，生成全分辨率 PNG；平台层只能交付经过当前令牌读取的 PNG 或其解码图像。画布纹理及覆盖预览没有导出资格。

领域层不依赖 egui、文件对话框或剪贴板库。Core 不依赖窗口和 UI；Editor 不访问网络、磁盘或系统剪贴板。原生平台函数返回明确的成功、取消或失败，由 Editor 接受当前操作结果后再更新 UI。

### 7.3 工具链和依赖

当前根 Workspace 声明 Rust 1.85，独立 POC 声明 1.88，正式整合前核实锁定依赖的实际最低版本并统一。eframe 0.36.2、rfd 0.15.4、arboard 3.6.1 是现有 POC 版本，不等同永久选型承诺；本轮不顺带升级到最新版本。固定依赖、编译器及构建目标后再形成可复建基线。

## 8 图像核心修改计划

### 8.1 保留的安全不变量

延续单张静态 PNG/JPEG、25 MiB 压缩输入与 24MP 解码像素上限。根据文件实际内容判断格式；EXIF 方向归一后建立统一坐标；遮挡填充为不透明 RGBA 17/24/39/255；无有效遮挡拒绝导出；使用新 PNG 编码，不携带原图层或源元数据。

25 MiB 和 24MP 是当前实现限制，不表示对应性能已经合格。若实测要求调整上限，先提出变更和兼容影响，经重新评审后更新代码、合同及测试。

### 8.2 需要补充的验证

覆盖截断、错误头、极端尺寸、EXIF 1 至 8、异常 APP1、边界矩形、PNG 附加数据及不支持格式。不能仅因新输出能解码就认定逐像素正确；遮挡范围、非遮挡像素、尺寸、方向和元数据应由测试分别检查。

保持五张冻结图及期望 RGBA 哈希不变。JPEG 的归一化像素以 V1 Rust 解码基线为准，不能用 Pillow JPEG 解码差异放宽输出要求。若确实改变解码器或颜色处理，单独提出兼容性决定，保留旧真值及差异报告。

### 8.3 性能修改的边界

先测解码次数和内存峰值，再决定缓存或缓冲复用。当前 POC 加载可能多次解码源字节，复核也有再次解码；这属于性能审查目标，不能未经测量声称泄漏。每次减少复制都需维持来源不可变、旧版本失效及真实 PNG 检查，不引入无必要的 unsafe 优化。

## 9 编辑领域模型完善计划

### 9.1 维持一套编辑真值

保留稳定遮挡 ID、来源像素半开区域、统一 Selection、单调 Revision 和文档身份。新增、移动、调整、删除及清空进入统一历史；拖拽预览不产生大量撤销项，提交一次手势仅产生一条历史。取消手势恢复原状，新编辑清除 redo，撤销不能复活旧成品。

GUI 可以保存临时指针位置、焦点和视口，但不能独立维护另一份权威遮挡列表。选区数值编辑若纳入首版，必须调用领域命令，拒绝越界、NaN、Inf、零区域和翻转，不在 GUI 中手写另一套裁剪规则。

### 9.2 版本与并发

Review、Copy 和 Save 均绑定 DocumentId、Revision、OperationId。修改、换图、撤销、重做及新手势按现有规则废弃旧输出和待处理结果。后台工作只返回带身份的结果，主线程核验后接纳；取消可先采用作废旧任务，避免不必要的并发框架。

系统剪贴板已写入的旧图无法自动收回。应用必须拒绝旧回调显示为当前图复制成功，但不能宣称操作系统已经撤销外部副作用。

### 9.3 测试补齐

在既有 33 项测试基础上按缺陷增加针对性用例：连续替图、手势取消、清空后撤销、无变化操作、历史上限、延迟结果、重复完成、交付失败后重试。几何性质可用边界或生成测试验证，无需为语言比例迁移所有 Python 测试。保留能独立检查 PNG 输出的外部工具。

## 10 画布与成品复核计划

### 10.1 坐标与交互

显式区分来源像素、GUI 逻辑坐标和屏幕物理像素。每次命中和拖动都从实际渲染图框转换；DPI、窗体位置和缩放变化后重新计算映射。固定鼠标下的缩放锚点，支持 Fit、100%、200%、连续缩放和平移；窗口变化不得偷偷修改来源区域。

100% 建议定义为一个来源像素对应一个屏幕物理像素，并在界面与测试中写明；GUI 布局继续使用逻辑点。若改用其他语义，应在 G01/G03 前确认并一致执行。八个手柄的命中尺寸随 DPI 保持可用，区域尺寸仍可最小为 1px。

### 10.2 显示质量与性能分离

现有 POC 将最长边降采样到最多 2048px，再用于编辑和成品显示；全尺寸导出仍走 Core。该做法不能单独证明 100% 原像素细节可复核。原生工作台应提供当前可视范围的原分辨率显示，至少在 100% 和 200% 可检查边缘、1px 与细小文字。

先选择最简单、满足 GPU 上限的显示方案：小图直接使用原尺寸纹理，大图按可视区加载原像素区域，Fit 使用缩略图。只有设备和资源测量表明必要时再引入分块或纹理缓存，不立即建设通用渲染引擎。导出始终与显示纹理解耦。

### 10.3 验收方法

用 T04 四角、中心、贴边和负方向区域，在 Fit/100%/200% 及不同 DPI 下执行同一任务，导出后独立解码并比较全图像素。截图仅证明画面，指针轨迹及最终遮挡坐标用于解释几何。G04 还需 24MP 原像素复核和缩放平移实测，不能只读 GPU 报告的纹理尺寸上限。

## 11 Windows 导入 保存与剪贴板计划

### 11.1 导入

文件选择、Explorer 拖放和系统图片粘贴归并到同一受限读取与解码入口。当前 POC 已有文件和拖放代码，尚无图片粘贴入口。粘贴需明确接受的图像格式、alpha 处理、尺寸上限及文本焦点规则；没有图像时给出可恢复提示，不能把文本路径当任意文件自动读取。

文件读取前检查可得大小，读取过程仍执行字节上限，避免先无限制读入再校验。候选图片通过解码与显示准备后才替换当前文档。所有替换入口共用丢弃确认，取消或错误保持旧编辑。

### 11.2 保存

首个正式 Rust 版本建议沿用“另存为新 PNG，拒绝覆盖既有文件”的保守策略，并明确告知用户；暂不加入覆盖确认流程。此策略是相对旧版的产品差异，必须在迁移矩阵中获得明确接受，不能默认为功能等价。

避免直接写入后留下被误认成成功的半成品。选择目标后用安全的新文件写入策略，处理短写、磁盘满、权限拒绝、同步失败、同名竞争和取消；仅清理由本次操作创建且确认身份的临时产物，不能删除或替换用户原有文件。以完整写入和当前版本结果为成功依据。

### 11.3 剪贴板

“复制图像”将当前 PNG 解码的图像交给系统。Windows 的 DIB/Bitmap 等格式不保证等于原 PNG 字节，因此按钮使用“复制图像”，文件保存使用“保存 PNG”。成功文案描述系统已接受图像，不承诺所有目标应用保留相同色彩、透明度或原始 PNG 文件数据。

至少在 Paint 与另一个真实支持图片粘贴的应用读取结果，分别报告尺寸、RGBA、透明度和方向。若目标格式会丢 alpha，应记录格式限制和允许的产品策略；未获得一致性证据前不得标记 G06 通过。遇到剪贴板占用或权限错误保留编辑并提供另存 PNG，不进行无限后台重试。

## 12 工作台体验与无障碍计划

### 12.1 优先完成的交互

让区域列表与画布同步选中，显示区域编号和像素尺寸，不提取截图中的私人文本。绘制、选择和平移模式有明确状态；Esc 取消活动手势或关闭临时面板，Delete 删除选区，撤销重做同时提供按钮及快捷键。文本框拥有焦点时，不抢夺输入、退格或系统粘贴。

Fit、100%、200% 提供直接入口；放大后支持平移与复核细节。生成、导入和交付有忙碌状态及事实反馈，错误信息说明可采取的下一步。关闭复核返回编辑时，只有真实修改才触发重新生成要求，规则由 Editor 状态决定。

### 12.2 完整键盘任务

要求用户无需鼠标也能导入、创建一个有效遮挡、选中、精确移动或调整、撤销、复核并交付。画布键盘创建可采用受控的初始矩形加像素输入，细节在工作台设计中确定。不能以能 Tab 到按钮代替完成核心任务。

Narrator 应读出工具名称、选中状态、区域编号和尺寸、忙碌、错误及交付结果。焦点在弹窗打开、取消、换图及错误后回到合理位置。AccessKit 功能已启用只证明依赖配置，不证明上述语义存在或可用。

### 12.3 视觉验收

使用空态、编辑、多框选择、原像素复核、错误、导入取消与小窗口等代表状态截图。检查文字完整、中文无缺字、焦点清晰、按钮命中、侧栏不遮住关键内容、成品没有编辑手柄。审查者记录可复现问题，不能把同一开发者截图自查描述为独立用户测试。

## 13 隐私与安全修改计划

### 13.1 核心威胁与控制

| 风险 | 控制目标 | 必须取得的证据 |
|---|---|---|
| 仅显示遮罩却交付原图 | 成品仅来自 Core 新 PNG | 遮挡及非遮挡像素对照 |
| 旧成品交付 | 文档 版本 操作身份核验 | 延迟及替换反例 |
| 源元数据或尾部载荷传播 | 新编码和输出结构约束 | PNG chunk CRC 元数据及尾部检查 |
| 异常输入耗尽资源 | 输入 像素与分配边界 | 异常样本、峰值资源和失败恢复 |
| 覆盖或损坏用户文件 | 首版只创建新文件 | 同名 源路径 竞争及部分写故障 |
| 图片或路径进入日志及网络 | 最小日志 无非必要网络能力 | 源码检查 进程网络和日志观测 |
| 依赖或包内容不明 | 固定锁文件 许可与构建身份 | 依赖清单 许可证 校验和及审查 |

### 13.2 运行与内存边界

不引入云服务、账号、遥测或后台自动更新。导入、编辑、复核、交付及退出场景都应观测应用进程的网络行为，并区分操作系统或其他进程流量。源码无网络调用与限定场景无流量分别记录，不能推广为所有环境绝对无网络。

不持久化图片历史或自动缓存源图。文档关闭释放引用，日志不记录图片字节、完整本机路径、私人文件名和截图文本。Rust 释放内存不等于安全擦除；系统剪贴板、交换文件、崩溃转储及已保存图像属于需明确说明的系统边界。

### 13.3 验证与审查

保留现有安全回归及独立输出检查，补齐具体差距。对输入解析、几何、导出、版本和文件操作安排独立审查；依赖漏洞检查和许可证审查分别出结论。必要的受控 fuzz 使用合成输入并限制资源，不能用依赖清单或一次无告警扫描宣称全面安全认证。

## 14 性能 稳定性与兼容性计划

### 14.1 设备与测量方法

首轮至少包含 Windows 11 x64 的真实集显或独显设备、100/125/150/200% DPI 和一组混合 DPI 双屏；若对外继续支持 Windows 10 x64，则增加真实 Windows 10 系统验证，并重新确认实际支持版本。8GB RAM 设备作为资源参考档，若无法取得则明确最低配置未验证。

记录 CPU、RAM、GPU、驱动、系统 build、显示器缩放、渲染后端、工具链、锁文件哈希及完整 SHA。使用固定合成 24MP 图片，分别测导入、首次显示、拖拽、复核、复制、保存和峰值内存。冷启动测 5 次；交互至少采 30 个样本；重复导入与复核 20 轮观察资源趋势。记录中位数、P95、最大值和原始样本。

### 14.2 候选性能预算

| 项目 | 建议预算 | 冻结条件 |
|---|---|---|
| 用户动作后可见反馈 | 100ms 内 | 先验证测量方法与设备 |
| 拖拽与平移帧时 | P95 不高于 33.3ms | 固定窗口 DPI 图片和 GPU |
| 24MP 首次可操作显示 | 3 秒内 | 实测解码及显示路径后确认 |
| 24MP 成品生成 | 5 秒内 | 固定遮挡数和输入格式 |
| 应用进程峰值工作集 | 1GiB 内 | 8GB 参考档及重复场景实测 |

这些数值是待评审目标，当前未测得，也未作为既有 G04 的通过门槛。按原合同先测量，再由负责人确认预算并冻结；若改变成功标准，重新确认相关 Gate A/B，不在失败后静默放宽。最终通过记录必须同时含数字、设备和方法。

### 14.3 优化次序

先减少重复解码及大字节复制，再处理纹理上传和可视区显示。若 UI 主线程因读取或编码长时间阻塞，用最小工作线程机制返回带版本的结果，UI 保持可取消或可报告状态。只有测量发现瓶颈后再做并行化、缓存或渲染细化。优化后复跑像素真值、旧结果失效和错误恢复。

## 18 V2 06 导出与交付任务包

### 18.1 P06 A 绑定唯一成品

梳理从生成、实际 PNG 解码复核到 Save/Copy 的完整路径。每次交付取当前身份对应的工件，避免再次从 GUI 遮挡层构造图片。复核图、保存 bytes 与用于复制的解码图像来自同一成品；记录各自哈希及格式差异。

### 18.2 P06 B 验证过期与恢复

模拟生成中换图、复核后移动框、撤销后保存、复制等待时替换以及旧回调到达。确认旧操作不会更新新文档状态。生成、解码、写文件、剪贴板失败后均可重试或另存，已有编辑不丢失。若操作同步执行导致无法人工触发竞态，使用受控适配层测试，并保留真实系统集成测试。

### 18.3 P06 C 独立检查输出

继续运行五张全图 RGBA 金样本，并补边缘、重叠、1px、负向矩形、EXIF、空遮挡与超限案例。PNG 检查覆盖尺寸、遮挡及非遮挡像素、结构、CRC、无源元数据与无尾部载荷。两应用回贴分别比较，不能用复制 API 返回值代替。

阶段出口是 S04/S05/S06 的证据闭合以及独立审查结论。任何隐私像素反例阻断下一阶段切换，不以重建金样本消除差异。
